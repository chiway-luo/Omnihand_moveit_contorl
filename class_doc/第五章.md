# 第五章 构建驱动与MoveIt的桥接功能包

## 创建功能包
```bash
cd src/hand_test
ros2 pkg create hand_control --build-type ament_cmake --dependencies rclcpp omnihand_node_msgs std_msgs sensor_msgs  --node-name hand_control
```

## 代码实现
- 代码内容详见hand_control功能包中的src/hand_control.cpp文件,这里不再赘述,主要实现了以下功能：
- 订阅底层驱动反馈的 10 个主动关节，并发布 `/joint_states`；被动 mimic 关节由 `robot_state_publisher` 根据模型计算。
- 监听 `/controller_joint_states`，严格按 10 个主动关节的名称和固定顺序映射为底层电机位置命令。
- 启动时先处于 `WAIT_ALIGN`，只有收到名称完整且唯一、数值有限、全部在限位内的状态，并连续 3 帧与真实反馈误差不超过 0.03 rad，才进入 `ARMED`。
- 运行中若出现状态超时、单帧跳变或跟踪误差超限，桥接会解除 armed 状态并停止继续下发。
- 相同目标会去重；只有底层发布成功后才更新去重基准，避免一次失败导致后续相同目标被错误丢弃。
- O10 的 USB-C 路径使用 SDK 默认位置控制模式，节点默认不再发送旧版 `control_mode` 指令。
- SDK 桥接节点在调用厂商库前再次校验向量长度、有限值和官方关节限位，防止无效输入越过 ROS 2 层。

## 启动边界

真实硬件的 MoveIt 规划、RViz 预览、轨迹控制和底层驱动统一由以下入口启动：

```bash
ros2 launch hand_control hand_control.launch.py
```

不要同时启动 `ros2 launch hand_test_bag hand_test.launch.py`。两个入口都会创建 `omnihand_node`，并发运行会争用 `/dev/omnihand_left`。
